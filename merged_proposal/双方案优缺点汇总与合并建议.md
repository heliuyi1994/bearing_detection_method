## 3. 两方案能力对照（模块级）

| 流水线阶段 | glm | kimi |
|---|---|---|
| 轴承几何/特征频率 | `fault_freqs.py`：内置库（SKF6205/6208/22216）+ 宽松命名匹配 + `--bearing-json` 自定义几何 | `bearing.py`：`Bearing` 类 + 单一 `sk6205()` 工厂，无轴承库 |
| 仿真器 | `simulate.py`：Randall 模型，恒速 | `simulator.py`：支持变速 `speed_ramp`，输出轴相位供角域重采样 |
| 预处理 | 无独立模块（`indicators.detrend` + `kurtogram.bandpass_signal`，sosfilt 非零相位） | `preprocessing.py`：独立模块，remove_dc / detrend / **sosfiltfilt 零相位**带通 |
| 时域指标 | `indicators.py`：9 项 + `health_hint` | `features.py`：10 项 |
| 选带 | `kurtogram.py`：Antoni 树状快速 Kurtogram 自适应选带 | 无 Kurtogram；`envelope.py:auto_resonance_band()` 固定启发式 `(fs/6, 0.45·fs)` |
| 包络解调 | `spectrum.py`：包络谱 + 幅值谱 + **倒频谱** | `envelope.py` + `spectrum.py`：Hilbert 包络谱；无倒频谱 |
| 谱峰/谐波匹配 | `matcher.py`：5 谐波、**局部邻域中位数基线**、**整数倍混淆消歧**、概率化置信度 | `diagnosis.py:fault_scores()`：3 谐波、**全局**中位数地板、固定阈值 15；另有 `HealthBaseline` 马氏距离基线（**未接入流水线**） |
| 流水线编排 | `diagnose.py`（`DiagnosisResult` 含全部中间量） | `pipeline.py`（`DiagnosisPipeline` / `DiagnosisReport`） |
| 报告 | `report.py`：单张四联图 + 中文文本 + JSON | `plotting.py` 7 个绘图函数 + `cli.py` 多张独立 PNG + `summary.json` |
| 数据加载 | `loaders.py`：csv/txt/dat/npy/npz/**mat（含 CWRU `DE_time` 解析）** | 无加载模块，仅读自建 npz |
| 变速/阶次/时频 | 无 | `order_analysis.py`（角域重采样阶次谱）、`timefreq.py`（STFT + 复 Morlet CWT）、变速仿真 |
| ML 特征 | 48 维五组（`ml/features.py`：时域 9 + 物理谐波突出度 20 + Kurtogram 7 + 频谱形态 11 + 包络形态 2） | 26 维三组（时域 10 + 包络谱峰地比 13 + 频域 3）+ 检测级 4 维冲击子集 |
| ML 架构 | two_stage：Stage1 **监督**二分类（概率校准、阈值可调），Stage2 条件 4 分类；`--arch flat` 消融 | `TwoStageModel`：Stage1 **只训健康样本的新奇检测**（EllipticEnvelope 默认 / IsolationForest），Stage2 SVM/RF/kNN 择优 |
| ML 评估 | **GroupKFold 防泄漏 + LOSO 跨工况 + 阈值工作点扫描** + 与传统方法 `--compare` | StratifiedKFold + 随机 train_test_split（**无分组防泄漏、无 LOSO**） |
| 文档 | `docs/design.md`（D1–D13）、`docs/principles.md`（11 章）、`SKILL.md` | `docs/` 八章（01–08）+ ML 设计规格 + 7 个教程 notebook |

两处常见先验的修正（盘点中核实）：

- JSON 报告**不是** glm 独有——kimi 也输出 `summary.json`；glm 独有的是四联图版式与中文文本报告。
- "多模型 zoo"**两侧都有**（glm：LinearSVM/RBF-SVM/RF/HistGB + GridSearch；kimi：SVM/RF/kNN + 两种检测器）。真正的差异在**监督方式**与**评估协议严谨度**。

## 4. 真实数据评测证据

### 4.1 第一批：81 条四类台架数据——评测口径（`analysis/common.py` 头部决策记录）

- 数据集：`labeled_dataset_4class/`，81 条 WAV（16 kHz，约 3 s），工厂标签四类：正常 10 / 外圈 20 / 内圈 29 / 滚珠 22。
- 轮次 A：统一 1150 rpm；轮次 B：逐文件 `fr_est`（9 条缺失回退 1150）。
- 两方案统一用 glm 的 Kurtogram 自适应选带（kimi 侧注入 `DiagnosisPipeline(band=...)`，贴近奈奎斯特的频带被夹取，81 样本中发生 38 次）。
- 真值 = 工厂标签（声称值，非拆解确认）；匹配容差 ±2%；FTF/cage 判决归"其他"（计错）。共 324 次诊断。

### 4.2 第一批：总体结果（与工厂标签一致率）

| 方案 | 轮次 A | 轮次 B | 行为画像 |
|---|---|---|---|
| glm | 19.8%（16/81） | **25.9%**（21/81） | **0 误报**、正常类 100%；但 71 个故障样本漏检 52 个 |
| kimi | 14.8%（12/81） | 21.0%（17/81） | **0 漏检**；但正常 10/10 全误报 |

分类别（A 轮 → B 轮）：

| 方案 | 正常 | 外圈 | 内圈 | 滚珠 |
|---|---|---|---|---|
| glm | 100% → 100% | 20% → **35%** | 6.9% → 6.9% | 0% → 9.1% |
| kimi | 0% → 0% | 10% → 20% | 20.7% → 24.1% | 18.2% → 27.3% |

### 4.3 第一批：三个比准确率更重要的发现

1. **分歧在门控，不在定类**。两方案整体判决一致率仅 19.8%/28.4%（κ = 0.14/0.20），但在 glm 检出的子集上，两方案故障类型一致率高达 **88%**（B 轮 23/26）——双方命中的是同一组物理谱峰，分歧主体是"glm 未检出 vs kimi 检出"。
2. **glm 的置信度有判别力，kimi 的没有**。glm B 轮正确样本置信度中位 0.1831 vs 错误样本 0.0477；kimi 的绝对分被全局基线稀释爆炸（正常组中位 2332 vs 健康阈值 15，超百倍），不具跨样本可比性。
3. **kimi 的健康阈值跨域结构性失效**。仿真标定的固定阈值 15（仿真健康分布 5.97–12.4）在真实数据上被击穿，导致"永远判故障"。其 `HealthBaseline` 马氏距离模块**正是为此设计但未接入流水线**。

补充：两方案存在批次互补（glm 下午批次好：morning 6.5% / afternoon 28.0%；kimi 恰好相反：25.8% / 8.0%），主报告原话建议"**kimi 触发检出 + glm 定位与复核**的融合策略在现场值得尝试"——v1 级联门控即由此而来，后被 §4.5 的实测修正为 v2。

### 4.4 第一批：标签质量是结论上限（口径声明）

- 12 条样本两方案**一致**但与标签矛盾，模式高度系统化（6 个"外圈"标签同判内圈等），疑似外圈/内圈标签（或台架记录）系统性错位；外圈组 20/20 全削波。
- 因此所有"准确率"只能表述为**与工厂标签的一致率**；低一致率"大部分失败可归因于数据条件而非算法本身"。统一方案的验收口径必须沿用此声明。

### 4.5 第二批：audio-assets 库音频评测（1349 条）与规则 v2 的诞生

**数据与口径**：MySQL `audio_labeling.audio_assets`（product_id=1），WAV 16 kHz 单声道约 3.8 s；轴承几何与第一批相同；转速范围 1100–1200 rpm 恒速（逐文件未知）。正常集 = status=1 共 **566** 条，异常集 = status=-1 共 **783** 条（其中轴承 168、摩擦 426、部位详细标签 86 条供参考）；description 为人工标注（声称值，口径同 §4.4）。合并方案原型：`merged_proposal/unified_prototype.py`；评测：`analysis/run_eval_audio_assets.py`。

**v1（级联门控 + 理论频率锚定）实测暴露两个结构性瓶颈**：

1. **触发级灵敏度塌陷**：健康总体冲击特征重尾（正常组峭度 p99≈332、最大 902），马氏距离椭球假设被尾部撑大（折外距离中位 0.36 vs p99 阈值 8.89）——p99 工作点下异常检出仅 9.3%。
2. **理论锚定结构性不可达**：92.6% 文件转速自估回退 1150 rpm，±2% 容差对应可达转速窗 [1127, 1173]，1100–1200 均匀假设下约一半文件对理论锚定匹配不可达。直接证据：轴承集复核级证据率在回退文件仅 23.6% vs 自估成功文件 40.0%。

**v2（盲梳检存在性 + 频带落入定位）**：先不依赖理论频率判"是否存在轴承故障特征"（周期冲击 → 包络谱谐波梳 + 倒频谱互证），再用理论频率定位——这正是 §2 第三轮 Q17–Q20 的规则，复跑全部 1349 条的对照：

| 指标 | v1 | v2 |
|---|---|---|
| 正常误报率 | 1.1%（6/566） | 2.1%（12/566） |
| 异常检出率 | 9.3%（73/783） | **32.3%**（253/783） |
| 轴承检出（全体口径） | 1.8%（3/168） | **48.8%**（定位 37 + 检出但未定位 45）/ 仅定位 22.0% |
| 摩擦检出（全体口径） | 15.5%（66/426） | 13.8%（59/426） |
| 86 条部位标签 argmax 参考 | 30.2% | 31.4% |
| 低置信 | 64 | 67 |

- **核心判据达成**：轴承全体口径 48.8%，显著突破 v1 理论锚定的结构性上限（复核级单级证据率 28%）；v2 匹配**完全不依赖转速**。
- **干扰防护有效**：51 个梳被标记排除（低频轴频族 40、工频 50 Hz 5、轴频谐波 6）；直接案例——正常文件 19638 的 50.26 Hz 梳本会被频带落入法误判外圈，防护拦截后正确判正常。
- **遗留短板**：正常误报翻倍至 2.1%；45 条轴承"检出但未定位"（梳基频集中 ~21–37 Hz 低频区，疑为实际转速低于标称窗或其他周期源）；摩擦路径仍受马氏触发塌陷约束（13.8%，29 条摩擦被判轴承、37 条未定位，清单单列建议人工复听）。
- 详细分析：`analysis/reports/audio_assets/音频资产库评测报告.md`（v1）与 `analysis/reports/audio_assets/rules_v2/规则V2对照报告.md`（v2 对照）。

## 5. 优缺点汇总

### 5.1 glm 优点

1. **选带能力最强**：Kurtogram 谱峭度自适应选带（`kurtogram.py`），两批评测均以其为统一选带；kimi 的 `auto_resonance_band()` docstring 也自承"真实数据应结合谱峭度选带"。
2. **匹配器工程严谨**：局部邻域中位数基线抗谱形衰减、整数倍混淆消歧、概率化置信度跨样本可比——第一批评测中置信度排序有判别力（§4.3-2）；其显著度引擎与理论频率解耦，v2 盲梳检的观测峰拾取正是复用它。
3. **0 误报行为可设计复现**："宁漏检不错判"策略在第一批数据上完全兑现（正常类 100%）。
4. **ML 评估协议最严**：GroupKFold 按 group 防泄漏 + LOSO 跨工况 + 阈值工作点扫描 + 与传统方法 `--compare` 交叉对比；特征含 20 维与 matcher 同源的物理谐波突出度（双轨设计）。
5. **工程配套全**：内置轴承库 + JSON 自定义几何、CWRU 等多格式加载器、四联图 + 中文文本 + JSON 三态报告、倒频谱（v2 盲梳检的互证支柱）、设计决策文档（D1–D13）。

### 5.2 glm 缺点

1. **漏检严重**：第一批 71 个故障样本漏检 52 个；55 条"未检出"是诚实的拒绝判决而非阴性结论——但现场拿到的只是"没报警"。
2. **强依赖转速先验**：第一批轮次 B 修正转速后 +6.1pp；第二批进一步量化——92.6% 转速回退时轴承集证据率仅 23.6%（自估成功文件 40.0%），理论锚定匹配对 rpm 误差超过 ±2% 的文件结构性不可达。**这正是 v2 规则要消除的依赖**。
3. **预处理欠规范**：无独立预处理模块，带通用的是非零相位 sosfilt（kimi 为零相位 sosfiltfilt）。
4. **无新奇检测路径**：Stage1 是监督式二分类，现场没有故障标注时无法训练（kimi 的 EllipticEnvelope 只训健康样本即可）。
5. 不支持变速工况（本合并已明确不需要，列出仅供完整）。

### 5.3 kimi 优点

1. **0 漏检的灵敏度**：第一批 81/81 全触发；其定类机制（谐波平均稀释巧合 + argmax）在错型判决中仍与共振带分布一致，说明灵敏度本身有价值，坏的是门控阈值。
2. **马氏距离健康基线**（`diagnosis.py: HealthBaseline`）：相对化、可域内重标定的健康基线思路——v2 中作为非轴承异常（摩擦）路径的辅助判据。
3. **预处理规范**：独立 `preprocessing.py`，零相位滤波（v2 已按此落地解调）。
4. **无监督 ML 路径**：Stage1 新奇检测只训健康样本，覆盖"现场无故障标注"场景；train.py 注释记录了 IF 检出率塌缩为 0 的教训。
5. **教程资产好**：7 个循序渐进的 notebook，教学结构值得统一 notebook 借鉴。
6. 变速仿真 / 阶次分析 / 自实现复 Morlet CWT（本合并不移植，列出仅供完整）。

### 5.4 kimi 缺点

1. **健康阈值跨域失效**：固定阈值 15 在第一批数据上被击穿两个数量级，正常 10/10 全误报——绝对阈值不可跨域迁移；v2 实测进一步表明，即使域内重标定，冲击特征的重尾分布也会让马氏椭球假设塌陷（触发级异常检出仅 9.3%），该类方法只能降级为辅助判据。
2. **匹配器简化版**：全局中位数基线被 24k 谱线稀释到 ~1e-6 导致比率爆炸；仅 3 谐波、无整数倍消歧。
3. **原生固定选带错过真实共振区**：`(2667, 7200) Hz` 完全错过第一批数据内圈/滚珠集中的 1–1.5 kHz 共振区。
4. **ML 评估有泄漏风险**：随机 train_test_split 无分组、无 LOSO，仿真准确率偏乐观。
5. **工程配套薄**：无轴承库（仅 6205 一个工厂）、无通用加载器、报告为多张散图 + summary.json。

## 6. 合并建议

### 6.1 总体策略与命名

- **以 glm 代码为起点，新建统一包** `bearing_unified_method/`（包名 `bearing_unified`，CLI `bearing-unified`）；原两姊妹包保留不动，继续作为对照与回归基准。
- 合并哲学一句话：**glm 出骨架（选带→解调→显著度引擎→评估→报告），kimi 出规范化与兜底（零相位预处理、健康基线辅助、新奇检测 Stage1）**；判别规则采用 v2：**先盲检轴承故障特征存在性，再参考理论频率定位**。
- 当前可执行原型：`merged_proposal/unified_prototype.py`（`rules="v1"|"v2"` 并存，v1 回归逐值一致），即统一包的设计蓝本。

### 6.2 统一流水线架构（v2 盲梳检，已采纳为基线）

```
原始信号
  → 预处理（移植 kimi preprocessing.py：去直流/去趋势/零相位带通）
  → Kurtogram 自适应选带（glm）→ 零相位解调 → 包络谱
  →【盲梳检：轴承故障特征存在性，不依赖理论频率】
      A. 观测峰驱动梳扫：局部邻域中位数显著度拾取显著峰（复用 glm matcher 显著度定义），
         以每个显著峰为候选基频 f0（约 20–150 Hz），验证 k·f0（k=2..5）谐波族，
         谐波得分 w_k=1/k 加权；偏好"能解释最多显著峰的最小基频"，同族去重
      B. 倒频谱互证：glm spectrum.real_cepstrum，q≈1/f0 处显著 quefrency 峰（含 rahmonics）
      → A∩B 都确认 = 存在轴承故障特征（可多梳）
      → 干扰防护：轴频谐波族（f0≈k×fr，fr∈[18.33,20]）与工频 50 Hz 梳打标排除
  → 有梳 → 判"异常-轴承" →【定位】频带落入法（频带表见下）
        → 理论频率复核（容差 ±4%）合成外圈/内圈/滚珠 3 类置信度（无保持架判别）
        → 落入空档 → fr_hyp=f0/阶次 反推补救 → 仍无解 → "检出但未定位"单列
  → 无梳 且 时域冲击异常（kimi HealthBaseline 马氏距离，域内标定，**辅助判据**）
        → 判"异常-非轴承（摩擦）"
  → 皆无 → 正常；证据皆弱 → 低置信单列
  → 转速自估（包络谱 1×fr 峰，回退 1150 rpm）：仅作记录与辅助，匹配不依赖
```

**定位频带表**（1100–1200 rpm 窄窗 → fr ∈ [18.33, 20.0] Hz，四类特征频带互不重叠）：

| 频带 Hz | 类别 |
|---|---|
| 32.2 – 35.2 | 滚珠（BSF 基频） |
| 47.3 – 51.6 | 外圈（BPFO） |
| 64.5 – 70.3 | 滚珠（2×BSF 主峰） |
| 81.1 – 88.4 | 内圈（BPFI） |

注意：该频带表由"转速窗 × 轴承几何"导出，是 v2 唯一的先验依赖——**现场工况（转速范围或轴承型号）变化时必须重算频带表**（§7 风险 2）。

**被否决的 v1 方案留档**：级联门控（马氏触发级 → glm matcher 理论锚定复核级）。否决依据（§4.5）：触发级在重尾健康总体上灵敏度塌陷（异常检出 9.3%）、理论锚定在 92.6% 转速回退下结构性不可达（轴承全体口径仅 1.8%）。原型中保留 `rules="v1"` 作对照基准。

### 6.3 移植清单（kimi → 统一包）

| # | 移植项 | 来源 | 目标位置 | 说明 |
|---|---|---|---|---|
| 1 | 马氏距离健康基线 + 域内标定流程 | `bearing_fault/diagnosis.py`（HealthBaseline） | `bearing_unified/baseline.py`（新增） | **v2 修订：降级为非轴承异常（摩擦）路径的辅助判据**，不再担任门控；重尾问题需 robust 化（§7 风险 3） |
| 2 | 零相位预处理模块 | `bearing_fault/preprocessing.py` | `bearing_unified/preprocessing.py` | v2 原型已按此落地（选带后零相位解调替代 glm 的 sosfilt） |
| 3 | 新奇检测 Stage1 后端 | `bearing_fault/ml/`（EllipticEnvelope 路径） | `bearing_unified/ml/` 作为 Stage1 可选后端 | 默认仍为 glm 监督式；覆盖"无故障标注"场景 |
| 4 | 教程 notebook 教学结构 | `bearing_kimi_method/notebooks/01–07` | 统一 notebook 的写法借鉴（非代码移植） | Q7：notebook 待统一 API 落地后编写 |

glm 侧既有能力直接构成主干：Kurtogram 选带、包络谱/倒频谱、matcher 显著度引擎（v2 观测峰拾取复用）、轴承库、加载器、四联图报告。

### 6.4 明确不移植（Q6：无变速场景）

- `order_analysis.py`（阶次分析）、`timefreq.py`（STFT/CWT）、`simulator.py` 的 `speed_ramp` 变速仿真。未来若出现变速需求，源码在对照包中仍在，可直接捡回。

### 6.5 ML 合并形态（Q10）

- 主干：glm 两阶段分层（Stage1 监督二分类 + Stage2 条件 4 分类，联合置信度 = p_abnormal × P(fault|abnormal)），48 维双轨特征，保留 `--arch flat` / `--no-physical` 消融开关。
- Stage1 增加可选后端：kimi 式新奇检测（EllipticEnvelope，只训健康样本），默认仍用监督式。
- 评估协议统一为 glm 的 GroupKFold + LOSO + 阈值工作点扫描 + 传统方法 `--compare`；kimi 的随机划分方式不保留。
- 与 v2 的关系：v2 是 DSP 判别规则；ML 合并形态不变。盲梳检的结构化输出（梳基频/谐波得分/定位结果）可作为 ML 物理特征族的增量候选，后续评估决定。

### 6.6 原理文档扩写计划（Q4：glm principles.md 为底本）

以 glm `docs/principles.md` 11 章为底本，新增/改写：

1. 新增"预处理与零相位滤波"章（移植项 2）；
2. 新增"**轴承故障特征存在性的盲检**"章（包络谱谐波梳观测峰梳扫 + 倒频谱互证 + 轴频/工频干扰防护）——v2 核心设计；

### 6.7 实施阶段与验收标准

- **阶段一（DSP 主干）**：建包迁移 glm 代码 → 移植清单 1/2 → **v2 盲梳检规则**（以 `merged_proposal/unified_prototype.py` 为蓝本）。
- **阶段二（ML）**：glm ML 迁移 → 移植清单 3 → 统一评估协议跑通。
- **阶段三（交付）**：统一 notebook（Q5 两段式）+ 原理文档扩写 + 验收。

验收标准（可证伪；audio-assets v2 实测为首轮基线）：

1. **单测**：glm 现有 100 项全部迁移通过；移植模块与盲梳检各补测试（梳扫/倒频谱互证/干扰防护/频带定位/未定位语义），测试总数 ≥ 110。
2. **真实数据验收**（复用 `analysis/` 评测框架：81 条第一批 + audio-assets 1349 条，结论沿用"与人工标注一致率"声明）：
   - 轴承全体口径检出率 ≥ v2 基线 48.8% 不回退；
   - 正常误报率 ≤ v2 基线 2.1%，并争取经干扰防护与阈值调优回落；
   - 摩擦检出率 ≥ v1 基线 15.5%（触发级 robust 化后）；
   - "检出但未定位"比例显著低于 v2 的 45/168，且每条可归因；
   - 81 条第一批数据上：正常类 0 误报保持。
3. **文档**：notebook 可从头执行到底（无头环境），原理文档各章与代码模块一一对应。

## 7. 风险与开放问题

1. **标签质量上限**：第一批 12 条系统性矛盾样本 + 外圈组全削波；第二批 description 同为人工标注（声称值）。对外的期望管理要前置，验收看门控行为指标而非单看一致率。
2. **v2 的先验依赖转移到频带表**：盲梳检消除了逐文件 rpm 依赖，但定位频带表由"转速窗 1100–1200 × 轴承几何"导出；现场转速范围或轴承型号变化时必须重算频带表，否则定位错位。45 条"检出但未定位"低频梳簇（~21–37 Hz）疑为实际转速低于标称窗——需现场复核转速假设。
3. **摩擦路径未解**：马氏触发在重尾总体上塌陷（摩擦检出 13.8%）；robust 化方向（log/秩变换、EllipticEnvelope、单特征分位数触发）已列出待做；29 条摩擦被判轴承、37 条未定位，需人工复听界定真混淆还是标注粒度问题。
4. **干扰防护依赖工况先验**：轴频谐波窗（fr∈[18.33,20]）与工频 50 Hz 假设随现场变化需重校；防护标记本身应入报告可审计。
5. **已知保守行为**：频带边缘 ±4% 准入容差与 matcher ±2% 谐波窗存在半档落差（边缘样本归入未定位而非错定位，可接受）。
6. **语义同步**："未检出"不等于健康确认；报告措辞、JSON 字段语义、使用说明需统一，避免误读沿入新包。
7. 开放问题（留给评审/实施）：摩擦触发 robust 化的选型；ML 阶段是否纳入盲梳检结构化特征；统一包是否保留 glm 的 `SKILL.md`；`merged_proposal/` 在合并实施完成后是否归档。
